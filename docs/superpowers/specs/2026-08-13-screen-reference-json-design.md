# 화면 좌표 구조화 JSON 설계

## 요약

추천 카드의 `2번째 줄 2번째` 같은 숫자형 좌표는 현재 코드가 직접 파싱해 `screen.columns`와 서버 추천 순서로 상품 ID를 계산한다. 그러나 `두번째 줄 두번째`, `두 번째 줄 두 번째`처럼 한글 수사를 쓴 좌표는 숫자 전용 정규식에 걸리지 않아 decompose LLM이 곧바로 `cart.productId`를 고르는 경로로 빠진다. 이 경로는 선택한 ID가 추천 목록 안에 있으면 허용 목록 가드가 오선택을 막지 못한다.

발화 전체를 숫자 표기로 정규화하지 않는다. 대신 screen이 실제로 주입된 decompose 호출에서만 다음 내부 JSON 필드를 추가한다.

```json
{
  "screenReference": {
    "kind": "grid",
    "row": 2,
    "column": 2
  }
}
```

LLM은 화면 좌표 의미를 구조화할 뿐 상품 ID나 배열 index를 계산하지 않는다. 서버는 검증된 화면 표면과 열 수를 사용해 `index = (row-1) × columns + (column-1)`을 계산하고 그 위치의 서버 보유 상품 ID만 사용한다.

## 목표

- `두번째 줄 두번째`, `두 번째 행 두 번째 칸`처럼 한글 수사를 포함한 명시적 그리드 지시를 구조화한다.
- LLM 산출을 상품 ID가 아닌 `row`·`column`으로 제한한다.
- 추천 상품 ID를 FE가 재전송하지 않는 위조 방지 경계를 유지한다.
- 숫자형 좌표의 기존 결정적 파서와 상품명·옵션·행 단독·열 우선 안전 가드를 보존한다.
- 잘못되거나 범위 밖인 좌표는 다른 상품을 추측하지 않고 재질문한다.
- screen이 없는 decompose 시스템 프롬프트는 기존 문자열과 바이트 단위로 동일하게 유지한다.

## 내부 JSON 계약

`screenReference`는 외부 API나 SSE 필드가 아니라 decompose LLM 1회 호출의 내부 산출 필드다.

```text
screenReference = null
                | {kind: "grid", row: integer|null, column: integer|null}
```

규칙은 다음과 같다.

1. 사용자가 현재 보이는 상품 그리드의 행과 열을 모두 지목할 때만 `kind="grid"`를 낸다.
2. `두번째`, `두 번째`, `둘째` 같은 표현은 LLM이 정수로 구조화한다.
3. `두 번째 옵션`, `두 개`, `두 줄 세트`, 상품 순번만 말한 경우에는 `screenReference=null`이다.
4. LLM은 `screenReference`를 근거로 `cart.productId`를 계산하지 않는다. 기존 cart 필드는 호환성을 위해 남지만 최종 좌표 ID의 권위가 아니다.
5. screen이 없는 호출에는 필드 스키마와 규칙을 프롬프트에 추가하지 않는다.

파서는 `kind`가 정확히 `grid`인 객체만 좌표 주장으로 인정한다. `row`·`column`은 기존 `_as_int` 규약에 따라 bool을 제외한 정수, 정수형 float, 숫자 문자열을 받아들인다. 1 미만이거나 누락된 값은 유효한 위치로 조용히 폴백하지 않고 "좌표를 주장했지만 유효하지 않음"으로 보존해 재질문으로 보낸다.

## 서버 해소 순서

`resolve_screen_reference`는 다음 우선순위를 지킨다.

1. 대화 맥락 지시, 상품명 직접 지목, 열 우선 표현 등 기존 양보 가드
2. 원문에서 코드가 직접 확인한 숫자형 완전 좌표
3. 원문에서 확인한 행 단독 표현 — LLM이 빠진 열을 채우지 못하게 재질문
4. 유효한 `screenReference.kind="grid"` 좌표
5. 기존 숫자형 전체 순번, ID, 지시대명사 규칙

따라서 숫자형 원문과 LLM JSON이 충돌하면 원문 결정적 파서가 이긴다. 상품명을 직접 말했거나 `두 번째 옵션`처럼 좌표가 아닌 강한 신호가 있으면 JSON 좌표가 상품 선택을 덮어쓰지 않는다.

JSON 좌표를 실제 상품으로 바꾸려면 다음 조건을 모두 만족해야 한다.

- 옵션 재질문 대기 상태가 아니다.
- 현재 해소 표면이 비어 있지 않다.
- 추천 카드 표면이면 `ordinal_span == turn_count`로 단일 목록 노출 순서가 증명됐다.
- `screen.columns`가 유효하다.
- `row`와 `column`이 모두 1 이상의 정수다.
- 계산한 index가 표면 배열 범위 안이다.

어느 조건이든 실패하면 `productId`를 추측하지 않고 기존 화면 위치 재질문 문구를 사용한다.

## 데이터 흐름

1. FE는 기존대로 `screen={pageType:"chat", columns:N}`만 보낸다. 추천 ID는 보내지 않는다.
2. 구매자 그래프는 screen이 활성화된 턴에만 screen 변형 decompose 프롬프트를 사용한다.
3. LLM은 `screenReference`에 좌표 의미만 구조화한다.
4. decompose 파서는 내부 `ScreenReference` 값으로 변환해 `RouteDecision`에 보관한다.
5. 구매자 그래프는 기존 `last_reco[:turn_count]` 표면과 `columns`를 준비하고 `screenReference`를 화면 해소기에 전달한다.
6. 화면 해소기가 서버 배열 index를 계산해 최종 `productId`를 확정하고, 기존 장바구니·찜 허용 목록과 Spring 검증이 이어진다.

`screenReference`가 존재하면 `mentions_screen_reference`의 숫자 정규식에 걸리지 않는 한글 수사 발화도 화면 참조 시도로 기록한다. 이는 장바구니·찜 삭제의 단일 항목 fallback이 사용자가 지목하지 않은 다른 항목을 선택하지 못하게 하는 기존 안전 계약을 유지한다.

## 대안 검토

### 채택: LLM 좌표 구조화 + 서버 ID 계산

자연어 수사 해석은 LLM에 맡기되 산술, 배열 경계, 상품 ID 선택은 결정적 코드가 담당한다. 전역 문자열 치환 없이 한글 표현을 받을 수 있고, 잘못된 좌표가 추천 목록 밖 ID를 생성할 수 없다.

### 기각: 발화 전체 한글 수사 정규화

`두 번째 옵션`, `두 줄 세트`, 상품명 속 표현까지 바꿀 수 있다. 좌표 문맥 전용 정규화로 좁혀도 별도 한국어 수사 문법과 범위 정책을 코드가 소유해야 해 이번 선택보다 유지보수 표면이 크다.

### 기각: LLM이 최종 `productId` 선택

현재 실패 경로다. 이웃 상품도 허용 목록 안이면 사후 가드가 오선택을 탐지할 수 없다.

### 기각: LLM이 배열 index까지 계산

행·열 의미 추출과 산술을 한 산출에 묶으면 어느 단계가 틀렸는지 검증하기 어렵다. `row`·`column`만 받고 index는 코드가 계산한다.

## 테스트 전략

1. screen 변형 프롬프트에만 `screenReference` 스키마와 한글 좌표·옵션 반례 규칙이 추가되는지 검증한다.
2. screen 없는 프롬프트가 기존 `_SYSTEM`과 바이트 동일한지 기존 테스트로 고정한다.
3. 유효한 JSON 좌표, 숫자 문자열, bool·0·음수·누락·잘못된 kind 파싱을 단위 테스트한다.
4. `두번째 줄 두번째 상품 담아줘`에서 LLM이 다른 `cart.productId`를 내도 전체 5번째 추천 상품이 선택되는 그래프 테스트를 추가한다.
5. `두 번째 옵션`, 행 단독, 열 우선, 상품명 직접 지목에서는 JSON 좌표가 기존 안전 가드를 덮어쓰지 않는지 검증한다.
6. 순서 미검증, columns 누락, 범위 밖, 유효하지 않은 좌표가 모두 담기 없이 재질문하는지 검증한다.
7. 통합 테스트에서 추천 ID 재전송 없이 한글 좌표 JSON이 Spring I-2의 올바른 `productId`로 이어지는지 검증한다.
8. 관련 테스트, 전체 unit, Ruff, 변경 파일 pre-commit과 Chrome E2E를 실행한다.

## 호환성과 범위

- 외부 FE·SSE·Spring·DB 스키마는 변경하지 않는다.
- `screenReference`는 내부 LLM JSON이며 저장하지 않는다.
- 새 의존성이나 범용 한국어 수사 파서를 추가하지 않는다.
- 기존 숫자형 좌표 파서는 제거하지 않는다. LLM JSON과 충돌할 때 더 강한 원문 증거로 사용한다.
- 순번만 말한 한글 표현의 일반화, 열 우선 좌표, 옵션 자연어 해석 확장은 범위 밖이다.

## 완료 조건

한글 수사 그리드 발화가 `screenReference`로 구조화되고, 서버가 검증된 추천 순서와 `columns`로 올바른 상품 ID를 계산해야 한다. 숫자형 좌표·상품명·옵션·모호성 안전 가드는 유지되고, 잘못된 좌표는 담기 없이 재질문해야 하며, 외부 와이어 계약과 screen 없는 프롬프트는 변하지 않아야 한다.

## 자체 검토

- 일반 텍스트 정규화와 좌표 구조화를 명확히 구분했다.
- LLM과 코드의 권위 경계를 `row/column` 대 `index/productId`로 분리했다.
- malformed JSON, 충돌, pending, 순서 미검증, 범위 밖 실패 경로를 명시했다.
- 외부 계약 변경이나 새 의존성 없이 기존 worktree와 Draft PR 범위 안으로 제한했다.
