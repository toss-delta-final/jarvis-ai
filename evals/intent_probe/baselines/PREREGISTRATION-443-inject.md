# 사전 등록 — #443 사전 기반 leg 주입 (후보를 재기 **전에** 고정)

작성 시점: 규칙을 앵커에 오프라인으로 돌려 본 직후, **실 LLM 팔을 한 번도 재기 전.**
이 파일은 리포 안에 커밋한다 — 라운드 1에서 사전 등록을 tmp 에 뒀다가 잃은 교훈의 적용이다.

## 처방

`decompose` 파싱부에서 **legs 가 비어 있는 `recommend` 턴**에 한해, 발화에서 카탈로그 카테고리
사전(`app/data/seller_categories.json`, 정본 DB 스냅샷)과 **정확히 일치하는 이름**을 찾아 그것을
leg 으로 주입한다(최장 일치, 2자 이상, `category=null`).

- **추측하지 않는다** — 사전에 있는 이름만 쓴다. `_SYSTEM` 의 "없는 카테고리명을 지어내지
  마세요" 규칙과 같은 정신이다.
- **모델 산출을 덮어쓰지 않는다** — legs 가 하나라도 있으면 발동하지 않는다.
- #465 후처리(총칭 head 억제)와 **순서가 중요하다**: 억제 → 주입 순이면 억제로 비워진 턴에
  주입이 다시 채울 수 있다. **주입은 억제보다 먼저** 판정하고, 억제된 턴에는 주입하지 않는다
  (구현에서 못박고 테스트로 고정할 것).

## 오프라인 사전 확인 (실 LLM 아님, 이미 수행)

앵커 73건에 규칙을 적용한 결과:
- `condition_only` 5발화 **매칭 0건** (#465 방향 안전)
- `named_category` 001~005 매칭(`과일`×3·`물티슈`·`텐트`), 006(`텀블러`)은 사전에 없음

## 문턱 (실 LLM 판정)

11셀(`named_category` 6 + `condition_only` 5) × **N=24**, 프롬프트는 현재 `_SYSTEM` 그대로.
base 는 `fast-2026-08-10-443-final-guard`(104/144 = 72.2%, `conditionOnly` 115/120)에 **1런 추가**
해 2점으로 만든다.

**채택 조건 — 셋 다 만족해야 한다.**

1. `namedCategoryHasLeg` 비율이 **base 두 런 최댓값 + 8%p 이상**, inject 2런 **모두**.
2. `conditionOnlyNoCategoryQuery` 비율이 **base 최솟값 − 5%p 이상**, inject 2런 모두.
3. **하드 불변식**: `condition_only` 셀에서 주입이 발동한 표본 **0건**. 1건이라도 있으면
   수치와 무관하게 **기각**한다(#465 를 되살리는 것이라 트레이드오프 대상이 아니다).

## 기각 시 처리

기각되면 `_SYSTEM` 도 코드도 바꾸지 않고, #443 은 `Part of` 로 남긴다. 문면 7종 기각 기록 옆에
"사전 기반 주입도 재서 기각" 을 수치와 함께 남긴다 — 다음 사람이 같은 시도를 반복하지 않도록.

## 그대로 유지되는 규약

출고물 == 측정물(런 manifest sha12 대조) · 런은 순차 · 단일 실행으로 판정 금지 ·
하락 축은 수치와 함께 정직 보고 · 새 이슈 금지.
